Quantum Effect Software Development Pipeline Bible

Version: 1.0 (Foundation)
Status: Approved
Engine: Unity 6000.5.5f1

1. Vision

Quantum Effect is not developed as a traditional Unity project.

It is developed as an AI-native software project.

Unity is the runtime.

The AI pipeline is the production environment.

The project is designed for long-term maintainability through modular, independently generated systems.

2. Core Philosophy

The software architecture follows five principles:

Principle 1

Simulation First

Gameplay emerges from interacting systems.

Never hard-code gameplay sequences when systems can naturally produce them.

Principle 2

Modularity

Every feature exists as an independent module.

Modules communicate through interfaces and events.

Principle 3

Data Driven

Content belongs in ScriptableObjects and data assets.

Logic belongs in C#.

Principle 4

Single Responsibility

Each class has one responsibility.

Each script has one responsibility.

One .cs file equals one class unless there is a compelling reason otherwise.

Principle 5

AI Native

Everything should be understandable by another AI session.

Every generated component should be self-documenting and conform to shared standards.

6. Coding Standards

Every generated script must:

Compile independently.
Follow the Single Responsibility Principle.
Include XML documentation for all public classes and methods.
Contain clear comments explaining non-obvious logic.
Avoid hard-coded content values where data assets are appropriate.
Prefer interfaces over direct concrete dependencies.
Minimize coupling between systems.
7. AI Development Rules

The AI should never:

Rewrite unrelated systems.
Merge unrelated classes into one file.
Change folder structures without explicit approval.
Break public APIs without documenting the impact.
Introduce hidden dependencies.

The AI should always:

Explain assumptions.
List generated files.
Describe dependencies.
Identify extension points.
Highlight future integration requirements.

10. Prompt Generation Philosophy

The coding AI is never prompted directly from a vague feature request.

Instead, a dedicated prompt-generation step produces a precise implementation prompt that specifies:

Objective
Scope
Responsibilities
Dependencies
File outputs
Acceptance criteria
Coding standards
Integration notes

This ensures consistency across all generated code.
